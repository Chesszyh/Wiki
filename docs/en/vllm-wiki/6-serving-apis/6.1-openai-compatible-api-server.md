## Purpose and Scope

This page documents the FastAPI-based HTTP server that exposes vLLM's inference capabilities through an OpenAI-compatible REST API. It covers the server's entry points, startup sequence, route registration, middleware stack, engine client lifecycle, and multi-process deployment modes.

For documentation on how chat messages and multimodal content are parsed before being dispatched to the engine, see [6.2. Chat Utilities and Message Processing](https://github.com/vllm-project/vllm/blob/7cc302dd/6.2. Chat Utilities and Message Processing) For structured output and tool-calling integration, see [6.3. ## CLI Entry Points

The vLLM CLI dispatches subcommands through the `CLISubcommand` base class. The `serve` subcommand is the primary entry point for the API server.

The dispatch logic in `ServeSubcommand.cmd()` examines `args.api_server_count`:

| Condition | Mode | Function |
| --- | --- | --- |
| `api_server_count == 1` | Single process | `run_server(args)` |
| `api_server_count > 1` | Multi-process (data parallel) | `run_multi_api_server(args)` |
| `api_server_count < 1` | Headless (engine only) | `run_headless(args)` |

## Server Startup Sequence

The key startup steps performed by `run_server_worker()` `<FileRef file-url="https://github.com/vllm-project/vllm/blob/7cc302dd/vllm/entrypoints/openai/api_server.py#L474-L530" min=474 max=530 file-path="vllm/entrypoints/openai/api_server.py">Hii</FileRef>`:

1.  **`setup_server(args)`** – validates arguments, binds the socket (TCP or Unix domain), sets `ulimit`, installs a `SIGTERM` handler `<FileRef file-url="https://github.com/vllm-project/vllm/blob/7cc302dd/vllm/entrypoints/openai/api_server.py#L419-L461" min=419 max=461 file-path="vllm/entrypoints/openai/api_server.py">Hii</FileRef>`.
2.  **`build_async_engine_client(args)`** – async context manager that creates the `AsyncLLM` engine and yields an `EngineClient` for the lifetime of the server `<FileRef file-url="https://github.com/vllm-project/vllm/blob/7cc302dd/vllm/entrypoints/openai/api_server.py#L78-L106" min=78 max=106 file-path="vllm/entrypoints/openai/api_server.py">Hii</FileRef>`.
3.  **`engine_client.get_supported_tasks()`** – queries the engine to discover which task types the loaded model supports.
4.  **`build_app(args, supported_tasks)`** – constructs the `FastAPI` application, registers all route routers, and applies middleware `<FileRef file-url="https://github.com/vllm-project/vllm/blob/7cc302dd/vllm/entrypoints/openai/api_server.py#L157-L238" min=157 max=238 file-path="vllm/entrypoints/openai/api_server.py">Hii</FileRef>`.
5.  **`init_app_state(engine_client, app.state, args, supported_tasks)`** – populates `app.state` with the engine client, serving models, tokenization service, and per-task serving handlers `<FileRef file-url="https://github.com/vllm-project/vllm/blob/7cc302dd/vllm/entrypoints/openai/api_server.py#L291-L379" min=291 max=379 file-path="vllm/entrypoints/openai/api_server.py">Hii</FileRef>`.
6.  **`serve_http(app, sock=sock, ...)`** – starts the uvicorn server loop `<FileRef file-url="https://github.com/vllm-project/vllm/blob/7cc302dd/vllm/entrypoints/launcher.py#L29-L29" min=29 file-path="vllm/entrypoints/launcher.py">Hii</FileRef>`.

## Engine Client Lifecycle

The engine client is managed by `build_async_engine_client()` and `build_async_engine_client_from_engine_args()` as async context managers.

Key behaviors:

-   **Forkserver Setup**: If `VLLM_WORKER_MULTIPROC_METHOD=forkserver`, the forkserver is pre-loaded with `vllm.v1.engine.async_llm` to optimize process spawning `<FileRef file-url="https://github.com/vllm-project/vllm/blob/7cc302dd/vllm/entrypoints/openai/api_server.py#L84-L91" min=84 max=91 file-path="vllm/entrypoints/openai/api_server.py">Hii</FileRef>`.
-   **V1 Engine Integration**: `AsyncLLM.from_vllm_config` initializes the V1 engine core, handling multi-modal cache resets upon startup `<FileRef file-url="https://github.com/vllm-project/vllm/blob/7cc302dd/vllm/entrypoints/openai/api_server.py#L136-L149" min=136 max=149 file-path="vllm/entrypoints/openai/api_server.py">Hii</FileRef>`.
-   **Graceful Shutdown**: The `finally` block ensures `async_llm.shutdown()` is called, cleaning up GPU resources and IPC sockets `<FileRef file-url="https://github.com/vllm-project/vllm/blob/7cc302dd/vllm/entrypoints/openai/api_server.py#L152-L154" min=152 max=154 file-path="vllm/entrypoints/openai/api_server.py">Hii</FileRef>`.
