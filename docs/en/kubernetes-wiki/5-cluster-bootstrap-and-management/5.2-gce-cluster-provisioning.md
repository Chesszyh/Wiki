## Purpose and Scope

This document describes the Google Compute Engine (GCE) cluster provisioning system in the Kubernetes repository. This system is responsible for creating, configuring, and bootstrapping Kubernetes clusters on GCE infrastructure, including master nodes, Linux worker nodes, and Windows worker nodes.

The provisioning system handles:

-   Configuration management and environment variable processing
-   Binary distribution via Google Cloud Storage
-   Master node initialization with etcd and control plane components
-   Worker node configuration for both Linux (GCI/Ubuntu) and Windows
-   PKI certificate generation and distribution
-   Network setup including IP aliases, firewall rules, and routing

For information about local development clusters, see [Local Development Environment](/kubernetes/kubernetes/5.2-gce-cluster-provisioning).

## Configuration System

The GCE provisioning system uses a hierarchical configuration approach with shell scripts that set environment variables consumed by provisioning logic.

### Configuration Files

| File | Purpose | Key Responsibilities |
| --- | --- | --- |
| `config-common.sh` | Shared utilities | Node count calculations, disk sizing, IP range calculations |
| `config-default.sh` | Production defaults | Standard cluster configuration, resource sizing |
| `config-test.sh` | Testing configuration | E2E test settings, debug features, higher resource limits |

### Key Configuration Variables

The configuration system exposes numerous environment variables. Key categories include:

**Cluster Topology:**

-   `NUM_NODES`: Number of Linux worker nodes
-   `NUM_WINDOWS_NODES`: Number of Windows worker nodes
-   `MASTER_SIZE`, `NODE_SIZE`: GCE machine types
-   `MASTER_DISK_SIZE`, `NODE_DISK_SIZE`: Disk sizes

**Networking:**

-   `ENABLE_IP_ALIASES`: Enable IP aliasing for pod IPs
-   `NODE_IPAM_MODE`: IP allocation mode (`RangeAllocator` or `CloudAllocator`)
-   `CLUSTER_IP_RANGE`: Pod CIDR range
-   `SERVICE_CLUSTER_IP_RANGE`: Service IP range
-   `NETWORK`, `SUBNETWORK`: GCE network configuration

**Images:**

-   `MASTER_IMAGE_FAMILY`, `MASTER_IMAGE_PROJECT`: Master node OS image
-   `NODE_IMAGE_FAMILY`, `NODE_IMAGE_PROJECT`: Linux worker node OS image
-   `WINDOWS_NODE_OS_DISTRIBUTION`: Windows version (e.g., `win2019`)

**Runtime:**

-   `CONTAINER_RUNTIME_ENDPOINT`: CRI endpoint path
-   `CONTAINER_RUNTIME_NAME`: Runtime name (e.g., `containerd`)

The system includes optimizations like:

-   **MD5-based deduplication**: Checks if tarball already exists in GCS with same hash before uploading ([cluster/gce/util.sh229-244](https://github.com/kubernetes/kubernetes/blob/2757a872/cluster/gce/util.sh#L229-L244))

-   **Fallback URLs**: Provides multiple regional URLs in preference order ([cluster/gce/util.sh334-366](https://github.com/kubernetes/kubernetes/blob/2757a872/cluster/gce/util.sh#L334-L366))

### Kubelet Configuration

The `config-ip-firewall()` function ([cluster/gce/gci/configure-helper.sh150-214](https://github.com/kubernetes/kubernetes/blob/2757a872/cluster/gce/gci/configure-helper.sh#L150-L214)) sets up iptables rules:

1.  **Enable loopback routing**: `sysctl -w net.ipv4.conf.all.route_localnet=1`
2.  **Accept inbound traffic**: Add ACCEPT rules for TCP/UDP/ICMP/SCTP
3.  **IP masquerading** (if `NON_MASQUERADE_CIDR=0.0.0.0/0`):
    -   Create `IP-MASQ` chain
    -   Exclude RFC 1918 and other reserved ranges
    -   MASQUERADE all other outbound traffic
4.  **Metadata concealment** (if `ENABLE_METADATA_CONCEALMENT=true`):
    -   Add local IP `169.254.169.252` for metadata proxy
    -   DNAT metadata server traffic to proxy on port 988/987
5.  **Metadata firewall** (if `METADATA_SERVER_FIREWALL_MODE=log`):
    -   Log metadata access from unapproved UIDs

-   Resources: Configurable via `cpurequest` and `memoryrequest`
-   Volume mounts: `/var/log`, `/run/xtables.lock`, `/lib/modules`

The label `node.kubernetes.io/kube-proxy-ds-ready=true` is added to nodes by `build-linux-node-labels()` ([cluster/gce/util.sh630-634](https://github.com/kubernetes/kubernetes/blob/2757a872/cluster/gce/util.sh#L630-L634)) to prevent two kube-proxy instances during cluster upgrades.
