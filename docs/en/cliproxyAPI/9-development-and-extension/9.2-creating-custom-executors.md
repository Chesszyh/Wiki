This page explains how to implement the `ProviderExecutor` interface to add support for a new AI provider backend. It covers the interface contract, the supporting types, common patterns used by all built-in executors, and how to register a custom executor with the running service.

For context on how executors fit into the broader request pipeline, see the [Provider Executor System](/router-for-me/CLIProxyAPI/3.4-provider-executor-system) architecture page. For registering executors when embedding CLIProxyAPI as a Go library, see [Using the Go SDK](/router-for-me/CLIProxyAPI/9.1-using-the-go-sdk). For how requests are translated between formats before being handed to an executor, see [Translation System Deep Dive](/router-for-me/CLIProxyAPI/9.4-translation-system-deep-dive).

## The ProviderExecutor Interface

Every provider backend is represented by a single interface defined in [sdk/cliproxy/auth/conductor.go28-43](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/sdk/cliproxy/auth/conductor.go#L28-L43)

```
type ProviderExecutor interface {
    Identifier() string
    Execute(ctx, auth, req, opts) (Response, error)
    ExecuteStream(ctx, auth, req, opts) (*StreamResult, error)
    Refresh(ctx, auth) (*Auth, error)
    CountTokens(ctx, auth, req, opts) (Response, error)
    HttpRequest(ctx, auth, req) (*http.Response, error)
}
```
| Method | Responsibility |
| --- | --- |
| `Identifier()` | Returns the provider key string (e.g. `"gemini"`, `"claude"`). Used to look up the executor and match against `auth.Provider`. |
| `Execute()` | Handles a single non-streaming request. Translates, calls upstream, translates response, returns payload. |
| `ExecuteStream()` | Handles a streaming request. Returns a `*StreamResult` with a channel of chunks. |
| `Refresh()` | Refreshes OAuth tokens for a given auth entry. No-op for API-key-only providers. |
| `CountTokens()` | Counts tokens for a request without generating a response. |
| `HttpRequest()` | Injects credentials into a pre-built `*http.Request` and executes it. Used by proxy passthrough routes. |

Sources: [sdk/cliproxy/auth/conductor.go28-43](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/sdk/cliproxy/auth/conductor.go#L28-L43)

### Auth

`Auth` ([sdk/cliproxy/auth/types.go46-96](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/sdk/cliproxy/auth/types.go#L46-L96)) carries all credential state for one account. Key fields used by executors:

| Field | Type | Purpose |
| --- | --- | --- |
| `Attributes` | `map[string]string` | Static config values: `api_key`, `base_url`, `proxy_url`, `priority` |
| `Metadata` | `map[string]any` | Mutable runtime state: `access_token`, `refresh_token`, `email`, `expired` |
| `Provider` | `string` | Provider key this auth belongs to |
| `ID` | `string` | Unique identifier used for logging and usage tracking |

### Request and Options

`Request` carries the model name (potentially with a [thinking suffix](/router-for-me/CLIProxyAPI/8.3-thinking-and-reasoning-configuration)), the request body as raw bytes, and optional metadata.

`Options` carries:

-   `SourceFormat` — the format the incoming request arrived in (e.g. `openai`, `claude`, `gemini`). Used to select the correct translation path.
-   `OriginalRequest` — the body before any CLIProxyAPI-side modifications, used as the translation source when payload config rules are applied.
-   `Alt` — an alternate mode string such as `"responses/compact"`.

## Implementing the Interface

### Identifier

Return a stable lowercase string that uniquely identifies your provider. This string is matched against `auth.Provider` when the manager dispatches a request.

```
func (e *MyExecutor) Identifier() string { return "myprovider" }
```
This string must match what is stored in the auth files under the `provider` key.

Sources: [internal/runtime/executor/gemini\_executor.go57](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/internal/runtime/executor/gemini_executor.go#L57-L57) [internal/runtime/executor/claude\_executor.go43](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/internal/runtime/executor/claude_executor.go#L43-L43)

### PrepareRequest

Inject provider credentials into an `*http.Request` that has already been constructed by the caller. Used by passthrough proxy routes.

The pattern across all built-in executors is:

1.  Extract credentials from `auth.Attributes` or `auth.Metadata`.
2.  Set `Authorization` (or a provider-specific header like `x-goog-api-key` or `x-api-key`).
3.  Apply any custom headers from `auth.Attributes` using `util.ApplyCustomHeadersFromAttrs`.

See [internal/runtime/executor/gemini\_executor.go59-74](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/internal/runtime/executor/gemini_executor.go#L59-L74) for an API-key example and [internal/runtime/executor/claude\_executor.go46-69](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/internal/runtime/executor/claude_executor.go#L46-L69) for OAuth + API-key switching logic.

---

### HttpRequest

Call `PrepareRequest` then execute the request using a proxy-aware HTTP client.

```
func (e *MyExecutor) HttpRequest(ctx context.Context, auth *Auth, req *http.Request) (*http.Response, error) {
    httpReq := req.WithContext(ctx)
    if err := e.PrepareRequest(httpReq, auth); err != nil {
        return nil, err
    }
    httpClient := newProxyAwareHTTPClient(ctx, e.cfg, auth, 0)
    return httpClient.Do(httpReq)
}
```
`newProxyAwareHTTPClient` is a package-level helper in `internal/runtime/executor` that creates an `*http.Client` respecting the `auth.ProxyURL` and global proxy settings from `e.cfg`.

Sources: [internal/runtime/executor/gemini\_executor.go76-90](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/internal/runtime/executor/gemini_executor.go#L76-L90) [internal/runtime/executor/claude\_executor.go71-85](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/internal/runtime/executor/claude_executor.go#L71-L85)

### Execute (Non-Streaming)

**Diagram: Execute Method Flow**

> **[Mermaid sequence]**
> *(图表结构无法解析)*

The canonical steps for a non-streaming `Execute` implementation, drawn from all built-in executors:

1.  **Reject unsupported modes early**

    Check `opts.Alt` for modes the executor does not support:

    ```
    if opts.Alt == "responses/compact" {
        return resp, statusErr{code: http.StatusNotImplemented, msg: "..."}
    }
    ```

2.  **Strip thinking suffix**

    ```
    baseModel := thinking.ParseSuffix(req.Model).ModelName
    ```

    `req.Model` may carry a budget suffix like `claude-opus-4-5(16000)`. Always use `baseModel` when calling upstream; keep `req.Model` for translation calls so budget metadata is preserved.

3.  **Set up usage reporting**

    ```
    reporter := newUsageReporter(ctx, e.Identifier(), baseModel, auth)
    defer reporter.trackFailure(ctx, &err)
    ```

    `trackFailure` uses the named return `err` to mark the request as failed in usage stats if the function returns a non-nil error.

4.  **Translate the request**

    ```
    from := opts.SourceFormat
    to := sdktranslator.FromString("myprovider")
    originalTranslated := sdktranslator.TranslateRequest(from, to, baseModel, originalPayload, false)
    translated := sdktranslator.TranslateRequest(from, to, baseModel, req.Payload, false)
    ```

    Use `opts.OriginalRequest` as `originalPayload` when it is non-empty; this is the pre-modification request body used as the baseline for payload config rules.

5.  **Apply thinking parameters**

    ```
    translated, err = thinking.ApplyThinking(translated, req.Model, from.String(), to.String(), e.Identifier())
    ```

6.  **Apply payload config overrides**

    ```
    requestedModel := payloadRequestedModel(opts, req.Model)
    translated = applyPayloadConfigWithRoot(e.cfg, baseModel, "myprovider", "", translated, originalTranslated, requestedModel)
    ```

7.  **Build and execute the HTTP request**

    Create the request, set auth headers, call `recordAPIRequest`, then `httpClient.Do`.

8.  **Log response metadata**

    ```
    recordAPIResponseMetadata(ctx, e.cfg, httpResp.StatusCode, httpResp.Header.Clone())
    ```

9.  **Handle errors**

    For HTTP error status codes, return `statusErr{code: httpResp.StatusCode, msg: string(body)}`. For 429 responses, populate `sErr.retryAfter` if the provider includes a retry delay.

10.  **Parse and publish usage**

    ```
    reporter.publish(ctx, parseMyProviderUsage(data))
    ```

    Implement `parseMyProviderUsage` to extract token counts from the response body and return a `usageDetail` struct. Look at `parseOpenAIUsage`, `parseGeminiUsage`, or `parseClaudeUsage` in the executor package as reference.

11.  **Translate the response**

    ```
    var param any
    out := sdktranslator.TranslateNonStream(ctx, to, from, req.Model, opts.OriginalRequest, translated, data, &param)
    resp = cliproxyexecutor.Response{Payload: []byte(out), Headers: httpResp.Header.Clone()}
    ```

### ExecuteStream (Streaming)

`ExecuteStream` follows the same setup steps as `Execute` up through building the HTTP request, but then:

1.  Check the HTTP response status **before** starting the goroutine. If the status is an error, read the body, close it, and return an error.
2.  Start a goroutine that reads lines from the response body using `bufio.Scanner` and sends translated chunks on a channel.
3.  Return `&cliproxyexecutor.StreamResult{Headers: httpResp.Header.Clone(), Chunks: out}` immediately.

```
out := make(chan cliproxyexecutor.StreamChunk)
go func() {
    defer close(out)
    defer httpResp.Body.Close()
    scanner := bufio.NewScanner(httpResp.Body)
    scanner.Buffer(nil, streamScannerBuffer) // 50MB
    var param any
    for scanner.Scan() {
        line := scanner.Bytes()
        appendAPIResponseChunk(ctx, e.cfg, line)
        // parse usage if terminal chunk
        chunks := sdktranslator.TranslateStream(ctx, to, from, req.Model,
            opts.OriginalRequest, translated, bytes.Clone(line), &param)
        for i := range chunks {
            out <- cliproxyexecutor.StreamChunk{Payload: []byte(chunks[i])}
        }
    }
    // flush [DONE] sentinel
    tail := sdktranslator.TranslateStream(ctx, to, from, req.Model,
        opts.OriginalRequest, translated, []byte("[DONE]"), &param)
    for i := range tail {
        out <- cliproxyexecutor.StreamChunk{Payload: []byte(tail[i])}
    }
    if err := scanner.Err(); err != nil {
        recordAPIResponseError(ctx, e.cfg, err)
        reporter.publishFailure(ctx)
        out <- cliproxyexecutor.StreamChunk{Err: err}
    } else {
        reporter.ensurePublished(ctx)
    }
}()
return &cliproxyexecutor.StreamResult{Headers: httpResp.Header.Clone(), Chunks: out}, nil
```
Key points:

-   `streamScannerBuffer` (50 MB) is a package-level constant in `internal/runtime/executor`.
-   Always send a `[DONE]` sentinel to `sdktranslator.TranslateStream` to flush any buffered state in stateful translators.
-   Send scanner errors on the chunk channel — the caller drains the channel and surfaces errors to the HTTP client.
-   Call `reporter.ensurePublished` after the scan loop completes normally. Call `reporter.publishFailure` on scan error.

Sources: [internal/runtime/executor/gemini\_executor.go212-338](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/internal/runtime/executor/gemini_executor.go#L212-L338) [internal/runtime/executor/claude\_executor.go230-402](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/internal/runtime/executor/claude_executor.go#L230-L402) [internal/runtime/executor/openai\_compat\_executor.go179-290](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/internal/runtime/executor/openai_compat_executor.go#L179-L290) [internal/runtime/executor/qwen\_executor.go157-247](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/internal/runtime/executor/qwen_executor.go#L157-L247)

### CountTokens

Count tokens using the upstream API (or locally if the provider does not offer a token counting endpoint).

### Refresh

`Refresh` is called by the `Manager`'s background refresh loop before a token expires. It must:

-   Return the same `*Auth` pointer if no refresh is needed (e.g., API-key only providers).
-   Return an updated `*Auth` with new token values in `auth.Metadata` after a successful refresh.
-   Return `(nil, err)` if the refresh fails — this will mark the auth as needing attention.

Providers that use only static API keys implement `Refresh` as a no-op:

```
func (e *MyExecutor) Refresh(_ context.Context, auth *Auth) (*Auth, error) {
    return auth, nil
}
```
For OAuth providers, the pattern from `ClaudeExecutor.Refresh` ([internal/runtime/executor/claude\_executor.go493-525](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/internal/runtime/executor/claude_executor.go#L493-L525)) is:

1.  Read `refresh_token` from `auth.Metadata`.
2.  Call the provider-specific token refresh service.
3.  Write the new `access_token`, `refresh_token`, and expiry back into `auth.Metadata`.
4.  Return the modified `auth`.

Sources: [internal/runtime/executor/gemini\_executor.go421-424](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/internal/runtime/executor/gemini_executor.go#L421-L424) [internal/runtime/executor/claude\_executor.go493-525](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/internal/runtime/executor/claude_executor.go#L493-L525) [internal/runtime/executor/codex\_executor.go560-597](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/internal/runtime/executor/codex_executor.go#L560-L597) [internal/runtime/executor/antigravity\_executor.go846-855](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/internal/runtime/executor/antigravity_executor.go#L846-L855)

## Common Helper Patterns

### Credential Extraction

The convention is to define a package-local function that extracts credentials from an `*Auth`:

```
func myCreds(a *cliproxyauth.Auth) (apiKey, baseURL string) {
    if a == nil {
        return "", ""
    }
    if a.Attributes != nil {
        apiKey = a.Attributes["api_key"]
        baseURL = a.Attributes["base_url"]
    }
    if apiKey == "" && a.Metadata != nil {
        if v, ok := a.Metadata["access_token"].(string); ok {
            apiKey = v
        }
    }
    return
}
```
This pattern is used by `codexCreds` ([internal/runtime/executor/codex\_executor.go676-690](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/internal/runtime/executor/codex_executor.go#L676-L690)) and `claudeCreds` ([internal/runtime/executor/claude\_executor.go757-771](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/internal/runtime/executor/claude_executor.go#L757-L771)).

### Request Logging

All built-in executors call `recordAPIRequest` before sending to upstream and `recordAPIResponseMetadata` / `recordAPIResponseError` after receiving the response. These write to the request/response log if logging is enabled (see [Request and Response Logging](/router-for-me/CLIProxyAPI/8.4-request-and-response-logging)).

```
recordAPIRequest(ctx, e.cfg, upstreamRequestLog{
    URL:       url,
    Method:    http.MethodPost,
    Headers:   httpReq.Header.Clone(),
    Body:      translated,
    Provider:  e.Identifier(),
    AuthID:    authID,
    AuthLabel: authLabel,
    AuthType:  authType,
    AuthValue: authValue,
})
// ... execute ...
recordAPIResponseMetadata(ctx, e.cfg, httpResp.StatusCode, httpResp.Header.Clone())
appendAPIResponseChunk(ctx, e.cfg, responseBodyBytes)
```
Populate `authID`, `authLabel`, `authType`, `authValue` from `auth.ID`, `auth.Label`, and `auth.AccountInfo()`.

### statusErr

Return `statusErr{code: int, msg: string}` for HTTP-level failures. This type is defined in the executor package and implements the error interface. The `Manager` reads the `code` field to populate the HTTP response to the client.

For 429 responses with a provider-supplied retry delay, populate `sErr.retryAfter` with a `*time.Duration`. The `Manager` will surface this as a `Retry-After` header.

Sources: [internal/runtime/executor/antigravity\_executor.go222-229](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/internal/runtime/executor/antigravity_executor.go#L222-L229) [internal/runtime/executor/claude\_executor.go173-181](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/internal/runtime/executor/claude_executor.go#L173-L181)

### Optional: ExecutionSessionCloser

If your executor maintains per-session state (e.g., WebSocket connections), implement `ExecutionSessionCloser` from [sdk/cliproxy/auth/conductor.go46-48](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/sdk/cliproxy/auth/conductor.go#L46-L48):

```
type ExecutionSessionCloser interface {
    CloseExecutionSession(sessionID string)
}
```
When `RegisterExecutor` replaces an existing executor with the same identifier, it calls `CloseExecutionSession(CloseAllExecutionSessionsID)` on the old one. The sentinel value `CloseAllExecutionSessionsID = "__all_execution_sessions__"` signals that all sessions should be torn down.

## Registering the Executor

Call `manager.RegisterExecutor` ([sdk/cliproxy/auth/conductor.go399-421](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/sdk/cliproxy/auth/conductor.go#L399-L421)) with your executor instance. The `manager` is the `auth.Manager` that was constructed during service initialization.

When using the Go SDK (see [Using the Go SDK](/router-for-me/CLIProxyAPI/9.1-using-the-go-sdk)), pass the executor to the `Builder`:

```
cliproxy.NewBuilder().
    WithExecutor(NewMyExecutor(cfg)).
    // ...
    Build()
```
When extending a running service directly, obtain the `auth.Manager` reference and call:

```
manager.RegisterExecutor(NewMyExecutor(cfg))
```
`RegisterExecutor` is safe to call at any time, including after the service has started. If an executor with the same `Identifier()` is already registered, the old one is replaced and `CloseExecutionSession` is called on it if it implements `ExecutionSessionCloser`.

You must also ensure auth records with `provider` set to your executor's identifier exist in the auth directory so the manager has credentials to assign to requests. See [Authentication Setup](/router-for-me/CLIProxyAPI/2.3-authentication-setup) for how to create auth files.

Sources: [sdk/cliproxy/auth/conductor.go399-421](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/sdk/cliproxy/auth/conductor.go#L399-L421)

## Implementation Checklist

| Step | Notes |
| --- | --- |
| Implement `Identifier()` | Use a lowercase string matching `auth.Provider` in auth files |
| Implement `PrepareRequest()` | Inject API key or Bearer token into request headers |
| Implement `HttpRequest()` | Call `PrepareRequest` + `newProxyAwareHTTPClient(...).Do` |
| Implement `Execute()` | Translate → call upstream → translate response |
| Implement `ExecuteStream()` | Translate → call upstream → goroutine feeding chunk channel |
| Implement `CountTokens()` | Use upstream API or local tokenizer |
| Implement `Refresh()` | No-op for API keys; token exchange for OAuth |
| Implement `CloseExecutionSession()` | Optional; only needed for stateful session management |
| Register with `Manager` | `manager.RegisterExecutor(myExecutor)` |
| Add auth files | Provider entries in the auth directory |
