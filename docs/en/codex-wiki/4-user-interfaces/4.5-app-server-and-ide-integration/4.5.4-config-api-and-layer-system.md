## Purpose and Scope

This page documents the configuration API exposed by the app-server and the layered configuration system that underpins Codex's runtime behavior. The Config API provides JSON-RPC endpoints for reading and writing configuration values, while the layer system determines how settings from multiple sources (MDM, system files, user files, project files, CLI arguments) are merged with precedence rules.

For information about authentication configuration, see [Authentication Modes and Account Management](/openai/codex/4.5.5-authentication-modes-and-account-management). For feature flag management, see [Feature Flags](/openai/codex/2.3-feature-flags). For core configuration types and schemas, see [Configuration System](/openai/codex/2.2-configuration-system).

## System Overview

The Codex configuration system operates on two distinct planes:

1.  **Layer System (Load-time)**: Merges configuration from multiple sources at session initialization using `ConfigBuilder` and `ConfigLayerStack` [codex-rs/core/src/config\_loader/mod.rs114-120](https://github.com/openai/codex/blob/d807d44a/codex-rs/core/src/config_loader/mod.rs#L114-L120)
2.  **Config API (Runtime)**: Provides JSON-RPC endpoints for reading effective configuration and writing persistent changes to the user layer [codex-rs/app-server/src/codex\_message\_processor.rs862-936](https://github.com/openai/codex/blob/d807d44a/codex-rs/app-server/src/codex_message_processor.rs#L862-L936)

## Configuration Layer System

### Layer Sources and Precedence

Configuration is assembled from multiple layers. The loader (`load_config_layers_state`) constructs a `ConfigLayerStack` where higher-precedence layers override lower ones [codex-rs/core/src/config\_loader/mod.rs114-120](https://github.com/openai/codex/blob/d807d44a/codex-rs/core/src/config_loader/mod.rs#L114-L120)

| 1 | `Admin` | Managed preferences (macOS device profiles) [codex-rs/core/src/config\_loader/mod.rs128-135](https://github.com/openai/codex/blob/d807d44a/codex-rs/core/src/config_loader/mod.rs#L128-L135) |

## Requirements and Constraints

### requirements.toml System

The `requirements.toml` file (and cloud-provided requirements) enforces hard constraints that cannot be overridden by user or project layers [codex-rs/core/src/config\_loader/mod.rs83-91](https://github.com/openai/codex/blob/d807d44a/codex-rs/core/src/config_loader/mod.rs#L83-L91)

**Enforced Constraints:**

-   **Sandbox Modes**: Restricts allowed `sandbox_mode` values (e.g., forcing `read-only`) [codex-rs/app-server-protocol/src/protocol/v2.rs737-750](https://github.com/openai/codex/blob/d807d44a/codex-rs/app-server-protocol/src/protocol/v2.rs#L737-L750)
-   **Network Access**: Global enable/disable for network tools [codex-rs/app-server-protocol/src/protocol/v2.rs737-750](https://github.com/openai/codex/blob/d807d44a/codex-rs/app-server-protocol/src/protocol/v2.rs#L737-L750)
