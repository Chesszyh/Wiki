This page documents the observability infrastructure of Codex, primarily implemented in the `codex-otel` crate. The system provides a unified interface for OpenTelemetry (OTEL) integration, encompassing metrics, distributed tracing, and structured session telemetry.

## Overview

Codex uses OpenTelemetry to monitor agent performance, tool execution, and model interactions. The telemetry system is designed to handle both long-running sessions and ephemeral CLI executions, supporting multiple export backends including OTLP (HTTP/gRPC) and internal analytics providers.

## The codex-otel Crate

The `codex-otel` crate provides the `OtelProvider`, which acts as the central registry for OTEL SDK components.

### OtelProvider and Initialization

The `OtelProvider` wraps the OpenTelemetry `TracerProvider`, `MeterProvider`, and `LoggerProvider`. It is typically initialized using the `build_provider` function in `codex-core`.

Key functions:

-   `build_provider`: Maps application `Config` to `OtelSettings` and constructs the provider `<FileRef file-url="https://github.com/openai/codex/blob/d807d44a/codex-rs/core/src/otel_init.rs#L16-L93" min=16 max=93 file-path="codex-rs/core/src/otel_init.rs">Hii</FileRef>`.
-   `codex_export_filter`: A filter predicate that ensures only events targeting `codex_otel` are exported, preventing noise from third-party libraries `<FileRef file-url="https://github.com/openai/codex/blob/d807d44a/codex-rs/core/src/otel_init.rs#L97-L99" min=97 max=99 file-path="codex-rs/core/src/otel_init.rs">Hii</FileRef>`.

### Export Routing Policies

Codex implements specific routing policies for sensitive data. For example, user prompts are logged to the `LoggerProvider` for debugging but are excluded from the `TracerProvider` (spans) to avoid leaking PII into distributed traces where only metadata (like prompt length) is recorded `<FileRef file-url="https://github.com/openai/codex/blob/d807d44a/codex-rs/otel/tests/suite/otel_export_routing_policy.rs#L95-L200" min=95 max=200 file-path="codex-rs/otel/tests/suite/otel_export_routing_policy.rs">Hii</FileRef>`.

## Session Telemetry

The `SessionTelemetry` struct is the primary interface for recording telemetry within a specific agent session (thread). It manages session-scoped metadata and ensures all recorded metrics and events are tagged correctly.

### Metadata Tagging

When `SessionTelemetry` records a metric, it automatically injects a standard set of tags:

-   `app.version`: The workspace version.
-   `model`: The model name (e.g., `gpt-4o`).
-   `session_source`: The originator (e.g., `cli`, `app-server`).
-   `auth_mode`: The authentication method used `<FileRef file-url="https://github.com/openai/codex/blob/d807d44a/codex-rs/otel/tests/suite/manager_metrics.rs#L51-L66" min=51 max=66 file-path="codex-rs/otel/tests/suite/manager_metrics.rs">Hii</FileRef>`.

## Feedback and Diagnostics

Codex includes a specialized "Feedback Tags" system for capturing diagnostic metadata that is attached to user feedback submissions.

### feedback\_tags! Macro

The `feedback_tags!` macro logs tracing events with a specific target (`feedback_tags`).
