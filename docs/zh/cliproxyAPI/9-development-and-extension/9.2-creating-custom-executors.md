## 用途与范围

执行器是负责向 AI 供应商发起实际 API 请求并处理响应转换的组件。通过实现 `ProviderExecutor` 接口，开发者可以添加对新 AI 平台的支持，或定制现有供应商的通信方式（例如通过 WebSocket 隧道传输请求）。

本页面定义了执行器接口，并提供了实现新执行器的分步指南。有关执行器在系统中如何被选取的背景信息，请参阅第 3.4 页。有关现有的基于 WebSocket 的执行器示例，请参阅第 8.7 页。

## `ProviderExecutor` 接口

所有执行器必须实现定义在 `sdk/cliproxy/auth/conductor.go` 中的 `ProviderExecutor` 接口。

### 接口定义

```go
type ProviderExecutor interface {
    // 基础元数据
    Identifier() string
    
    // 执行逻辑
    Execute(ctx context.Context, auth *Auth, req *Request, opts *Options) (*Response, error)
    ExecuteStream(ctx context.Context, auth *Auth, req *Request, opts *Options) (<-chan StreamChunk, error)
    
    // 可选能力
    CountTokens(ctx context.Context, auth *Auth, req *Request) (*UsageDetail, error)
    Refresh(ctx context.Context, auth *Auth) (*Auth, error)
    
    // 低级访问
    PrepareRequest(req *http.Request, auth *Auth) error
    HttpRequest(ctx context.Context, auth *Auth, req *http.Request) (*http.Response, error)
}
```

### 方法说明

| 方法 | 职责 |
| --- | --- |
| `Identifier()` | 返回唯一的供应商键 (例如 `"my-ai-provider"`)。 |
| `Execute()` | 处理非流式请求。负责翻译和错误映射。 |
| `ExecuteStream()` | 处理 SSE 流。必须返回一个用于异步分块的通道。 |
| `CountTokens()` | 本地或远程计算令牌使用情况。 |
| `Refresh()` | 使用刷新令牌更新 OAuth 凭据。由后台刷新程序调用。 |
| `PrepareRequest()` | 将认证标头 (如 API 密钥) 注入到 HTTP 请求中。 |
| `HttpRequest()` | 封装具有代理支持和请求记录功能的底层网络调用。 |

**来源：** [sdk/cliproxy/auth/conductor.go28-43](https://github.com/router-for-me/CLIProxyAPI/blob/c66cb0af/sdk/cliproxy/auth/conductor.go#L28-L43)

## 实现步骤

### 1. 定义执行器结构

创建一个新结构体，包含配置、日志记录器及任何必要的中间件。

```go
type MyProviderExecutor struct {
    provider string
    cfg      *config.Config
    client   *http.Client
}

func NewMyProviderExecutor(cfg *config.Config) *MyProviderExecutor {
    return &MyProviderExecutor{
        provider: "my-provider",
        cfg:      cfg,
        client:   util.NewProxyHTTPClient(cfg),
    }
}
```

### 2. 实现请求翻译

执行器应当使用翻译系统将入站请求（通常为 OpenAI 格式）转换为目标格式。

```go
func (e *MyProviderExecutor) Execute(ctx context.Context, auth *Auth, req *Request, opts *Options) (*Response, error) {
    // 翻译请求
    translatedBody := sdktranslator.TranslateRequest(
        opts.SourceFormat, 
        sdktranslator.FromString("my-format"), 
        req.Model, 
        req.Payload, 
        false,
    )
    
    // 发起 HTTP 请求
    httpReq, _ := http.NewRequestWithContext(ctx, "POST", e.endpoint, bytes.NewReader(translatedBody))
    e.PrepareRequest(httpReq, auth)
    
    resp, err := e.client.Do(httpReq)
    // ...
}
```

### 3. 处理流式传输 (SSE)

流式传输需要逐行读取响应并将其发送至通道。

```go
func (e *MyProviderExecutor) ExecuteStream(ctx context.Context, auth *Auth, req *Request, opts *Options) (<-chan StreamChunk, error) {
    ch := make(chan StreamChunk, 10)
    
    go func() {
        defer close(ch)
        // ... 读取 SSE 流 ...
        for line := range scanner.Lines() {
            translatedChunk := sdktranslator.TranslateStream(line, ...)
            ch <- StreamChunk{Payload: translatedChunk}
        }
    }()
    
    return ch, nil
}
```

## 最佳实践

1.  **使用 `recordAPIRequest`**：始终调用 `recordAPIRequest` 和 `recordAPIResponseMetadata` 以启用管理 API 中的日志查看功能 (见第 8.4 页)。
2.  **错误映射**：将供应商特定的错误码映射到标准的 HTTP 状态码，以保持一致的客户端行为。
3.  **支持代理**：始终使用 `util.NewProxyHTTPClient` 尊重用户的全局代理设置。
4.  **脱敏 (Sanitization)**：在记录日志前，确保从请求中剥离或脱敏 API 密钥。

## 注册自定义执行器

创建好执行器后，必须将其注册到 `Service` 实例中。

```go
svc := cliproxy.NewBuilder().Build()
myExec := NewMyProviderExecutor(cfg)

// 向认证管理器注册
svc.GetAuthManager().RegisterExecutor(myExec)
```

## 实现检查清单

| 任务 | 描述 |
| --- | --- |
| 实现 `Identifier()` | 确保与认证文件中的 `type` 匹配 |
| 实现 `Execute()` | 支持非流式请求 |
| 实现 `ExecuteStream()` | 处理 SSE 流和分块翻译 |
| 实现 `PrepareRequest()` | 注入标头 (API 密钥, Bearer 令牌) |
| 实现 `Refresh()` | (可选) 实现 OAuth 令牌交换 |
| 实现 `CloseExecutionSession()` | (可选) 仅在有状态会话管理时需要 |
| 向 `Manager` 注册 | `manager.RegisterExecutor(myExecutor)` |
| 添加认证文件 | 在认证目录中添加供应商条目 |
