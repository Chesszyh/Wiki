# Wiki 翻译设计规范

**日期**: 2026-04-03
**主题**: LlamaFactory Wiki 的高质量技术翻译

## 1. 概述
目标是将 LlamaFactory Wiki 从英文翻译为专业的简体中文。虽然 `zh/` 目录中已经存在部分翻译，但其质量参差不齐（自动化翻译、连词、未翻译术语）。本设计专注于使用并行子代理进行完整、高保真的重新翻译。

## 2. 架构与策略

### 2.1 多代理并行化
- **并发性**: 使用 8 个并行子代理 (`general-purpose`) 以最大化吞吐量。
- **批处理**: 每个子代理处理约 5 个 Markdown 文件。
- **上下文共享**: 为所有子代理提供共享的“翻译风格指南”，以确保术语一致性（例如，“quantization” -> “量化”，“checkpoint” -> “检查点”）。

### 2.2 翻译流水线
1. **扫描**: 识别根目录中的所有 40 个 `.md` 文件（不包括 `zh/`）。
2. **批处理**: 按目录/主题对文件进行逻辑分组，以帮助子代理保持上下文。
3. **执行**: 使用专门的翻译提示词调用子代理。
4. **后处理**: 确保所有非 Markdown 文件（图像等）都镜像到 `zh/`。
5. **验证**: 进行结构和语法检查。

## 3. 翻译质量标准

### 3.1 风格与语气
- **专业性**: 严谨、自然、专业。
- **格式**: 不总结、不遗漏、不连接英文单词（例如，使用 "Python versions" 而非 "Pythonversions"）。
- **一致性**: 跨所有 40 个文件统一术语。

### 3.2 保留规则
- **Markdown 标记**: 保留所有 `#`、`-`、`*`、`>` 等。
- **代码块**: 不要翻译 ` ``` ` 或行内 ` ` ` 其中的内容。
- **外部链接**: 原样保留所有 GitHub 链接、URL 和图像路径。
- **Mermaid 图表**: 保留图表逻辑；仅在适当（或技术化保留英文）的情况下翻译标签。

## 4. 验证与成功标准
- **结构完整性**: `zh/` 必须是源文件的 1:1 镜像（由 `verify_zh_mirror.py` 验证）。
- **Markdown 有效性**: 没有损坏的链接、代码块或表格。
- **风格检查**: 对 10% 的文件进行人工抽检，以确保语言准确性。

## 5. 部署计划
1. 使用 `writing-plans` 创建实施计划。
2. 并行批量执行翻译。
3. 最终清理与验证。
