## 概览

Codex 使用 OpenTelemetry 监控代理性能、工具执行和模型交互。该遥测系统旨在同时处理长生命周期会话与短生命周期 CLI 执行，并支持包括 OTLP（HTTP/gRPC）和内部分析提供方在内的多种导出后端。

## codex-otel Crate

`codex-otel` crate 提供 `OtelProvider`，其作为 OTEL SDK 组件的中心注册表。

### OtelProvider 与初始化

`OtelProvider` 封装了 OpenTelemetry 的 `TracerProvider`、`MeterProvider` 与 `LoggerProvider`。它通常通过 `codex-core` 中的 `build_provider` 函数初始化。

关键函数：

-   `build_provider`：将应用 `Config` 映射到 `OtelSettings` 并构建 provider `<FileRef file-url="https://github.com/openai/codex/blob/d807d44a/codex-rs/core/src/otel_init.rs#L16-L93" min=16 max=93 file-path="codex-rs/core/src/otel_init.rs">Hii</FileRef>`。
-   `codex_export_filter`：过滤谓词，确保仅导出目标为 `codex_otel` 的事件，避免第三方库噪声 `<FileRef file-url="https://github.com/openai/codex/blob/d807d44a/codex-rs/core/src/otel_init.rs#L97-L99" min=97 max=99 file-path="codex-rs/core/src/otel_init.rs">Hii</FileRef>`。

### 导出路由策略

Codex 为敏感数据实现了特定路由策略。例如，用户提示词会记录到 `LoggerProvider` 用于调试，但会从 `TracerProvider`（span）中排除，以避免将 PII 泄漏到分布式追踪中；在追踪中仅记录元数据（如提示词长度） `<FileRef file-url="https://github.com/openai/codex/blob/d807d44a/codex-rs/otel/tests/suite/otel_export_routing_policy.rs#L95-L200" min=95 max=200 file-path="codex-rs/otel/tests/suite/otel_export_routing_policy.rs">Hii</FileRef>`。

## 会话遥测

`SessionTelemetry` 结构体是在特定代理会话（thread）内记录遥测的主要接口。它管理会话范围元数据，并确保所有记录的指标与事件都被正确打标。

### 元数据标签

当 `SessionTelemetry` 记录指标时，它会自动注入一组标准标签：

-   `app.version`：工作区版本。
-   `model`：模型名称（例如 `gpt-4o`）。
-   `session_source`：来源方（例如 `cli`、`app-server`）。
-   `auth_mode`：所使用的认证方式 `<FileRef file-url="https://github.com/openai/codex/blob/d807d44a/codex-rs/otel/tests/suite/manager_metrics.rs#L51-L66" min=51 max=66 file-path="codex-rs/otel/tests/suite/manager_metrics.rs">Hii</FileRef>`。

## 反馈与诊断

Codex 包含专门的“反馈标签”系统，用于采集附加到用户反馈提交中的诊断元数据。

### feedback\_tags! 宏
