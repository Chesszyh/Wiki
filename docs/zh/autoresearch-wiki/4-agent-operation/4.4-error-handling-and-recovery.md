# 错误处理与恢复

相关源文件

-   [program.md](https://github.com/karpathy/autoresearch/blob/e6d79c12/program.md?plain=1)

## 目的与范围

本文档描述了 autoresearch 系统在自治实验过程中如何检测、分类并从错误中恢复。其涵盖超时检测、崩溃诊断流程、简单修复尝试，以及在 `results.tsv` 中记录失败。

该系统旨在实现完全自治，使智能体能够在无人干预的情况下处理常见问题，例如内存溢出（OOM）错误、语法错误或执行超时。

---

## 错误类别

在自治运行期间，autoresearch 系统会遇到三类主要错误：

| 错误类型 | 原因 | 检测方法 | 恢复策略 |
| --- | --- | --- | --- |
| **超时** | 实验超过 10 分钟墙钟时间上限 | 墙钟计时器监控 | 杀死进程，丢弃更改，记录为 crash |
| **崩溃（OOM）** | GPU VRAM 耗尽 | 非零退出码 | 丢弃更改，记录为 crash，尝试不同方法 |
| **崩溃（代码错误）** | 语法错误、运行时异常、缺失导入 | 非零退出码 | 若问题简单则修复，否则丢弃并记录为 crash |

系统通过智能体判断来区分**可轻松修复的琐碎错误**（拼写错误、缺失导入）与**根本性问题**（架构问题、由模型规模过大导致的 OOM）。

## 超时检测与处理

### 预期运行时间

每个实验的预期总运行时间约为 **7 分钟**：

-   5 分钟：固定训练预算（[program.md23](https://github.com/karpathy/autoresearch/blob/e6d79c12/program.md?plain=1#L23-L23)）
-   约 1-2 分钟：启动、编译和数据加载。
-   约 30 秒：通过 `prepare.py` 中的 `evaluate_bpb` 进行最终评估 [prepare.py321-334](https://github.com/karpathy/autoresearch/blob/e6d79c12/prepare.py#L321-L334)

### 超时阈值

如果一次实验的总墙钟时间超过 **10 分钟**，则视为超时失败。该阈值既考虑了启动和 `torch.compile` 时间的正常波动，也能防止进程失控运行。

## 崩溃检测与诊断

### 退出码监控

智能体使用 shell 重定向来执行实验，以捕获所有输出供后续诊断：

```
uv run train.py > run.log 2>&1
```
执行完成后，智能体会检查 shell 的退出码。如果该退出码非零，就会启动诊断流程。

### 诊断流程

检测到崩溃时，智能体遵循以下步骤：

1.  **日志检查**：运行 `tail -n 50 run.log` 读取 Python 栈追踪 [program.md101](https://github.com/karpathy/autoresearch/blob/e6d79c12/program.md?plain=1#L101-L101)
2.  **错误分类**：识别该错误是“dumb and easy to fix”的拼写问题，还是根本性缺陷 [program.md110](https://github.com/karpathy/autoresearch/blob/e6d79c12/program.md?plain=1#L110-L110)
3.  **指标验证**：使用 `grep "^val_bpb:\|^peak_vram_mb:" run.log` 确认未产出指标 [program.md100-101](https://github.com/karpathy/autoresearch/blob/e6d79c12/program.md?plain=1#L100-L101)

### 常见崩溃原因

| 崩溃类型 | 典型错误信息 | 根本原因 | 可修复？ |
| --- | --- | --- | --- |
| **OOM（CUDA）** | `RuntimeError: CUDA out of memory` | 模型对 GPU VRAM 来说过大 | 否 - 需要缩小规模 |
| **语法错误** | `SyntaxError: invalid syntax` | `train.py` 修改中的拼写错误 | 是 - 简单修复 |
| **导入错误** | `ImportError: cannot import name` | `train.py` 中缺失导入 | 是 - 添加导入 |
| **形状不匹配** | `RuntimeError: mat1 and mat2 shapes` | 模型中的张量维度错误 | 可能 - 检查逻辑 |

## 失败实验的记录

### results.tsv 条目格式

失败实验会记录到 `results.tsv`（制表符分隔）中，并使用哨兵值以确保日志可被 `analysis.ipynb` 等分析工具解析。

| 字段 | crash 时的取值 | 原因 |
| --- | --- | --- |
| `commit` | 7 字符哈希 | 标识失败尝试 |
| `val_bpb` | `0.000000` | 失败哨兵值 [program.md75](https://github.com/karpathy/autoresearch/blob/e6d79c12/program.md?plain=1#L75-L75) |
| `memory_gb` | `0.0` | 失败哨兵值 [program.md76](https://github.com/karpathy/autoresearch/blob/e6d79c12/program.md?plain=1#L76-L76) |

## 用于恢复的 Git 状态管理

### 执行前提交模式

智能体采用**执行前提交**策略以实现干净回滚。这可确保即使发生崩溃，导致崩溃的代码状态也会保存在 Git 历史中（直到 reset），并可在 `results.tsv` 中引用。

1.  **修改**：智能体 hack `train.py` [program.md97](https://github.com/karpathy/autoresearch/blob/e6d79c12/program.md?plain=1#L97-L97)
2.  **提交**：将更改提交到本地分支 [program.md98](https://github.com/karpathy/autoresearch/blob/e6d79c12/program.md?plain=1#L98-L98)
3.  **执行**：启动 `uv run train.py` [program.md99](https://github.com/karpathy/autoresearch/blob/e6d79c12/program.md?plain=1#L99-L99)
4.  **评估/恢复**：若运行更差或崩溃，智能体执行 `git reset` 回到上一个成功的“frontier”提交 [program.md104](https://github.com/karpathy/autoresearch/blob/e6d79c12/program.md?plain=1#L104-L104)

### 分支历史

Git 分支（例如 `autoresearch/mar5`）维护一条**干净的线性历史**，其中仅包含成功改进。失败实验（崩溃或退化）会记录在 `results.tsv` 中，但其代码更改会通过 reset 从 Git 分支中清除。

## 智能体自治性与韧性

### 无需人工干预

智能体被指示**永不停止**实验循环 [program.md112](https://github.com/karpathy/autoresearch/blob/e6d79c12/program.md?plain=1#L112-L112) 这意味着：

-   **自我纠正**：如果发生崩溃，智能体必须独立诊断。
-   **持续性**：如果一个想法失败（崩溃），智能体必须“think harder”并尝试不同的架构改动 [program.md112](https://github.com/karpathy/autoresearch/blob/e6d79c12/program.md?plain=1#L112-L112)
-   **判断力**：智能体使用自身判断决定何时修复过于复杂，以及该想法应被放弃 [program.md101](https://github.com/karpathy/autoresearch/blob/e6d79c12/program.md?plain=1#L101-L101)

### 处理卡住状态

如果智能体陷入卡住状态（例如连续多次崩溃），它被允许回退或尝试激进的架构改动，以找到可行的前进路径 [program.md106](https://github.com/karpathy/autoresearch/blob/e6d79c12/program.md?plain=1#L106-L106) 首要目标是在 `train.py` 环境约束内最小化 `val_bpb`。
