## 目的与范围

本文档描述 Kubernetes 仓库中的 Google Compute Engine（GCE）集群配置系统。该系统负责在 GCE 基础设施上创建、配置并引导 Kubernetes 集群，包括主节点、Linux 工作节点和 Windows 工作节点。

该配置系统负责：

-   配置管理与环境变量处理
-   通过 Google Cloud Storage 分发二进制
-   主节点初始化（含 etcd 和控制平面组件）
-   Linux（GCI/Ubuntu）与 Windows 工作节点配置
-   PKI 证书生成与分发
-   网络设置（包括 IP 别名、防火墙规则和路由）

关于本地开发集群的信息，请参见 [Local Development Environment](/kubernetes/kubernetes/5.2-gce-cluster-provisioning)。

## 配置系统

GCE 配置系统采用分层配置方式，通过 shell 脚本设置环境变量，供后续配置逻辑消费。

### 配置文件

| 文件 | 用途 | 关键职责 |
| --- | --- | --- |
| `config-common.sh` | 共享工具 | 节点数量计算、磁盘尺寸计算、IP 范围计算 |
| `config-default.sh` | 生产默认值 | 标准集群配置、资源规格 |
| `config-test.sh` | 测试配置 | E2E 测试设置、调试特性、更高资源上限 |

### 关键配置变量

配置系统暴露了大量环境变量。关键分类包括：

**集群拓扑：**

-   `NUM_NODES`：Linux 工作节点数量
-   `NUM_WINDOWS_NODES`：Windows 工作节点数量
-   `MASTER_SIZE`、`NODE_SIZE`：GCE 机型
-   `MASTER_DISK_SIZE`、`NODE_DISK_SIZE`：磁盘大小

**网络：**

-   `ENABLE_IP_ALIASES`：是否启用 Pod IP 的 IP 别名
-   `NODE_IPAM_MODE`：IP 分配模式（`RangeAllocator` 或 `CloudAllocator`）
-   `CLUSTER_IP_RANGE`：Pod CIDR 范围
-   `SERVICE_CLUSTER_IP_RANGE`：Service IP 范围
-   `NETWORK`、`SUBNETWORK`：GCE 网络配置

**镜像：**

-   `MASTER_IMAGE_FAMILY`、`MASTER_IMAGE_PROJECT`：主节点操作系统镜像
-   `NODE_IMAGE_FAMILY`、`NODE_IMAGE_PROJECT`：Linux 工作节点操作系统镜像
-   `WINDOWS_NODE_OS_DISTRIBUTION`：Windows 版本（如 `win2019`）

**运行时：**

-   `CONTAINER_RUNTIME_ENDPOINT`：CRI endpoint 路径
-   `CONTAINER_RUNTIME_NAME`：运行时名称（如 `containerd`）

来源： [cluster/gce/config-default.sh1-178](https://github.com/kubernetes/kubernetes/blob/2757a872/cluster/gce/config-default.sh#L1-L178) [cluster/gce/config-test.sh1-320](https://github.com/kubernetes/kubernetes/blob/2757a872/cluster/gce/config-test.sh#L1-L320) [cluster/gce/config-common.sh17-118](https://github.com/kubernetes/kubernetes/blob/2757a872/cluster/gce/config-common.sh#L17-L118)

### 网络防火墙配置

`config-ip-firewall()` 函数（[cluster/gce/gci/configure-helper.sh150-214](https://github.com/kubernetes/kubernetes/blob/2757a872/cluster/gce/gci/configure-helper.sh#L150-L214)）用于设置 iptables 规则：

1.  **启用回环路由**：`sysctl -w net.ipv4.conf.all.route_localnet=1`
2.  **接受入站流量**：添加 TCP/UDP/ICMP/SCTP 的 ACCEPT 规则
3.  **IP 伪装**（若 `NON_MASQUERADE_CIDR=0.0.0.0/0`）：
    -   创建 `IP-MASQ` 链
    -   排除 RFC 1918 及其他保留网段
    -   对其余出站流量执行 MASQUERADE
4.  **元数据隐藏**（若 `ENABLE_METADATA_CONCEALMENT=true`）：
    -   添加本地 IP `169.254.169.252` 作为元数据代理
    -   将元数据服务器流量 DNAT 到 988/987 端口代理
5.  **元数据防火墙**（若 `METADATA_SERVER_FIREWALL_MODE=log`）：
    -   记录来自未授权 UID 的元数据访问

### kube-proxy DaemonSet 配置

当 `KUBE_PROXY_DAEMONSET=true` 时，kube-proxy 以 DaemonSet 而非静态 Pod 方式运行：

**DaemonSet 配置：**

-   节点选择器：`node.kubernetes.io/kube-proxy-ds-ready=true`（节点配置期间设置）
-   节点选择器：`kubernetes.io/os=linux`（仅 Linux 节点）
-   容忍：可在所有节点（含 master）上运行
-   资源：通过 `cpurequest` 和 `memoryrequest` 配置
-   卷挂载：`/var/log`、`/run/xtables.lock`、`/lib/modules`

标签 `node.kubernetes.io/kube-proxy-ds-ready=true` 会由 `build-linux-node-labels()`（[cluster/gce/util.sh630-634](https://github.com/kubernetes/kubernetes/blob/2757a872/cluster/gce/util.sh#L630-L634)）添加到节点，防止集群升级期间出现两个 kube-proxy 实例。
